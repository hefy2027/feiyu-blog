作为一个一线开发，平时跟 AI 打交道的时间越来越长。用了一阵子之后发现，好用的就那么几个——碰上对的场景，省掉的是整段重复劳动。写代码一条线，写文章宣传一条线，再日常飞书协作。顺手盘了一下现在最常碰的 10 个。

## 写代码

### 1. project-analysis（代码库分析）

动手写代码之前，先把仓库丢给 `project-analysis` 出一份完整的项目分析报告——12 个章节，从项目概览、技术栈版本、功能清单到系统架构、核心业务流程、数据模型、API 清单、企业级评估，最后落到关键发现和改进建议。整个过程逐章走：每写一章先加载研究指南，再独立做一轮 Glob / Read / Grep 调研拿第一手代码证据，写完回读自检通过才进下一章。产出是 `docs/<项目名>-analysis.md` 里像人工编写的正式文档。这步把「写到一半才发现根本不了解那块代码」的坑挡掉了。

> project-analysis 是我自己写的自定义 skill，安装方式见文末。

![project-analysis 对话触发截图](https://i.ibb.co/hxth5ssF/project-analysis-chat.png)

![project-analysis 生成的 12 章分析报告示例](https://i.ibb.co/cXZ6L3FB/project-analysis-report.gif)

### 2. Grill-me（拷问式对练）

分析完项目，动手之前先开一场 `/grilling`。把方案丢进去，AI 围着追问，直到漏洞和没想清的边角全磨透。比如给项目设计新功能，AI 不会说"好主意"，而是追着问边界和失败路径，逼出来的东西比我闷头想的结实得多。

![Grill-me /grilling 会话截图](https://i.ibb.co/39vT957S/grill-me-session.png)

### 3. fireworks-tech-graph（技术图表）

分析完了、方案也磨过了，该把架构画出来。多账户怎么统一管 DNS、Workers、存储、AI 推理，光靠文字谁都看不明白。`fireworks-tech-graph` 是专门出技术图表的，但它不是随便糊一张——有固定的工作流：先归类图型（架构图、数据流、时序图、C4 评审、云部署拓扑、网络拓扑等），按类型套对应的布局规则，从 12 套预设风格里选一套（浅色白底到终端暗色都有），再生成 SVG。生成完还得过一道关——跑一遍几何校验，查箭头有没有穿盒体、文字有没有溢出、标注有没有重叠，然后视觉审查，最后出 SVG + PNG。关键链路还能直接出 GIF 动图。我一句话丢给 agent，出来的图是经过检验的，放进文章里经得起看。

![cf-manager 多账户管理架构图](https://i.ibb.co/GvzkNncF/fireworks-arch-diagram.png)

### 4. Superpowers 全套（元技能）

`using-superpowers` 是 Superpowers 体系的入口元技能，来自 GitHub 上的 `obra/superpowers`。它不干具体活，只立一条规则：**动手前先确认有没有该用的 skill，哪怕只有 1% 的概率适用也得调起来**。

后面的流水线分两条。**Build 线**——接需求就开工：`brainstorming` 苏格拉底式提问，澄清需求、产出设计文档 → `using-git-worktrees` 创建隔离工作空间 → `writing-plans` 把方案拆成 2~5 分钟的原子任务 → `subagent-driven-development` 每任务派一个全新子 agent 并行搬砖，中间穿插 `test-driven-development`（RED → GREEN → REFACTOR）和 `requesting-code-review`（对照计划审查，严重问题直接阻断）→ 最后 `finishing-a-development-branch` 收尾。**Debug 线**——修 bug 走这条：`systematic-debugging` 四阶段根因分析（根因调查 → 模式分析 → 假设与测试 → 实施），未经根因调查不得修复；`verification-before-completion` 五步门控，没跑过验证不许说搞定了。

![Superpowers 驱动开发流水线](https://i.ibb.co/20kBjz71/superpowers-pipeline.png)

### 5. GitHub（gh CLI 工作流）

代码写完、review 过了，最后一步是提交管理。以前经常在 merge 环节搞乱分支线——要么 rebase 方向反了，要么忘了把 base 切回 main，结果 PR 里带了一堆不该带的 commit。现在一句指令搞定。说「开个 PR」，agent 自动跑 `gh pr create`，写好标题和描述；说「用堆叠 PR 合并」，它逐个把分支 rebase 到 main、切 base、squash 并进去——中间遇到冲突会停下让我手动解，绝不自己强推。整个过程从开 PR 到合并完，我不碰命令行，只看结果。

## 写文章 · 宣传

### 6. humanizer-zh（中文去 AI 味）

README、技术文档、PR 描述写完，提交前过一遍 `humanizer-zh`。把草稿喂进去，夸大象征、宣传腔、三段式排比、谄媚语气之类的东西刮掉，换成人话，最后还给个五维质量评分。举个实际例子——同样讲 cf-manager 发布：

> **改写前**：「cf-manager 的发布，标志着个人开发者在 Cloudflare 多账户运维领域迈出了关键一步，彰显了开源精神在持续演变的技术格局中的重要作用。」
>
> **改写后**：「cf-manager 发布了。对个人开发者来说，在 Cloudflare 上管多个账户一直是件麻烦事，这次算是个不错的突破口。也再次说明，开源这件事在技术不断变化的今天，依然很有意义。」

前者像新闻稿，后者像工位上跟隔壁同事说的原话。评审和接手的人都不会膈应。

![humanizer-zh 对话触发截图](https://i.ibb.co/d4vvnBH4/humanizer-chat.png)

### 7. imgbb-api（图床上传）

文章写好了，封面得配图。翻一翻我博客，封面全是 `i.ibb.co/...` 的链接。把图丢给 agent，说「传到 imgbb 拿直链」，几秒后回我一个可分享链接，粘进 frontmatter 的 `image` 字段就完事。以前我都是打开 ImgBB 网页手动拖图，现在一句指令搞定。

![博客文章中 imgbb 直链的使用效果](https://i.ibb.co/cK75RyQM/imgbb-cover-example.png)

### 8. HyperFrames（用 HTML 做视频）

给开源项目做宣传，以前觉得做视频是另一个工种的事。现在跟 agent 说「把 cf-manager 面板做成一支 60 秒宣传片」，HyperFrames 自己按意图选工作流、跑渲染，最后给我一支 MP4。比例按平台自动定，我不用操心。偶尔也用 `faceless-explainer` 把架构文章转成讲解视频。

![HyperFrames 生成的宣传片截图](https://i.ibb.co/pr0nRcr8/hyperframes-video-frame.gif)

### 9. gzh-design（公众号排版）

文章写完、视频出了，还要发公众号。`gzh-design` 把 Markdown 转成能直粘贴进微信编辑器的 HTML，自带主题组件库，按题材自动推荐风格——教程类走"摸鱼绿"、深度观点走"红白色系"、随笔走"留白禅意风"。章节编号、代码高亮、引言卡片、目录、签名一版到位，我拿回来粘进编辑器就完事。效果直接看本文就是


## 日常协作

### 10. 飞书全套（Lark 套件）

飞书这组 skill 随 `lark-cli` 安装自带，底层 27 个全就绪。我用得上的场景很集中——产出对接文档、排查记录、架构方案，一句指令让 agent 写成飞书在线文档，直接推到团队面前共享查看。`lark-markdown` 处理云盘里的 `.md` 文件，`lark-im` 偶尔收发消息。核心就一句话：本地想好的东西，无摩擦推到团队面前。

![飞书在线文档共享协作效果](https://i.ibb.co/YBrk9Hd2/lark-doc-example.png)

## 一句话总结

> 写代码这条线：`project-analysis` 摸底 → `grill-me` 磨方案 → `fireworks-tech-graph` 画架构 → `Superpowers` 驱动的 `brainstorming` / `writing-plan` / `subagent-driven-development` / `requesting-code-review` → `github` 收尾。写文章宣传这条线：`humanizer-zh` 去味 → `imgbb-api` 配图 → `HyperFrames` 出视频 → `gzh-design` 排公众号。日常协作：`飞书全套` 把文档推到团队面前。

回头一看，每段代码、每篇文章，都踩在对应的 skill 上。鱼游得慢没关系，工具顺手就行。

公众号后台回复「Skill」，获取这 10 个 skill 的安装方式。
