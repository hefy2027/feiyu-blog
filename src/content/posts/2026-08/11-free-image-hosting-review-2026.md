## 先说清楚：图床是什么，又为什么需要它

先讲明白再往下看，这跟我平时怎么写博客直接相关。

我习惯用 Markdown 写技术文章，每篇都要配几张截图和示意图，图都是以 `![说明文字](图片直链)` 的形式嵌进正文，所以图床简单说就是个「专门存图片、返回直链（URL）的在线服务」：我把本地截图传上去，它给我一个形如 `https://xxx/abc.jpg` 的地址，填进 Markdown 渲染出来就是一张图。

有人会问，图存自己电脑、丢进项目文件夹不行吗？不行。网页只能显示能通过公网 URL 访问到的图片：我发到网上的教程，读者打开的是远程页面，他电脑上没有我的本地截图，自然加载不出来。

Git 仓库对二进制又不友好，几十 MB 的图塞进去仓库体积暴涨、克隆变慢。文档、论坛、笔记这些场景更没法把图「打包」发给每个读者，只能给一个随时能打开的链接。

所以一句话：只要我的内容要出现在别人的屏幕上，就需要一个把图片「放上网、给出链」的地方。而「免费图床」是在这需求上再省掉存储和流量开销，代价是稳定性和额度的不确定性，这不确定性恰恰是我下面要实测的重点。

## 我不想再看到灰底红叉了

前阵子有读者在评论区问：「你那篇教程里的截图怎么全挂了？」点开自己半年前写的博文，十几张配图齐刷刷变成了灰底红叉。那一刻我习以为常，免费图床跑路这种事，这几年我至少撞上三次。每次都一样：精心配好的图，某天集体消失，满屏裂链接。

问题不在我，在于我把所有蛋都放在了同一个免费篮子里。于是这次我不想再赌运气：不看别人的推荐、不搜「十大图床」之类的文章，干脆自己打开浏览器，把市面上叫得出名字的图床一个个点开。12 个里 4 个已经进不去了，剩下 8 个能用的，每个都看完免费方案、亲手试了上传才下笔。

所以这篇文章不只告诉你「还有哪些图床能免费用」，更想说清楚我怎么搭一套不依赖单一图床的上传流程，以及每个图床实测踩到的坑。

## 我的图床组合思路

踩过三次坑后，我对免费图床的核心要求只有三条：

1. 别绑死生产：博客配图不能只挂在一个图床。一条挂了，全站裂图。
2. 上传要一键：手动去网页拖图、复制直链，写一篇文章配十张图就烦死了。我用自己封装的 skill 自动上传并替换文章里的图片引用，不用再手动搬。
3. 额度留余量：单图大小、每日张数、分辨率限制，要够日常写作用，别写到一半被限流。

基于这三条，我最终的组合是：ImgBB 当主力存图 + 路过图床当稳的备线 + 自封装的 skill 统一上传替换。下面先讲这套 skill 怎么工作，再讲每个图床实测。

> 提醒：免费额度是会变的。我记录的是 2026 年 8 月的数据，三个月后可能已调整。真要用于生产，务必自己再点进官网确认一遍当前免费档。

## 用我自己封装的 skill 把上传变成一键操作

我自己封装了一组 skill 专门干这件事，核心就两步：把本地图片传到图床拿到直链，再把文章里的本地图片引用批量替换成直链。

写文章时截图往本地一丢，跑一下 skill，文章里 `![](./assets/screenshot.png)` 就自动变成 `![](https://图床/abc.jpg)`，不用再手动去网页拖图、复制链接。这套 skill 底层走的就是图床的 HTTP 上传接口。

### 图床的 API 长什么样

以 ImgBB 为例，上传接口大致是这样：

```bash
curl -F "image=@./screenshot.png" \
     "https://api.example-bed.com/1/upload?key=YOUR_API_KEY"
```

聚合图床（底层整合了多家云存储、上传时可切线路）的多线路上传同理，提交 token + 图片源即可：

```bash
curl -F "token=YOUR_TOKEN" \
     -F "src=@./screenshot.png" \
     "https://api.example-bed.com/upload"
```

我的 skill 就是把这些调用封装起来、再负责把返回直链写回文章。端点地址是接口必需参数，不同图床返回体里直链字段名不一样，skill 里按各自的 API 文档对一下字段即可。

## 逐个图床实测：能用的都试了

下面 8 个是我当天逐个点开、确认能访问且看完免费方案的。

### 1. 路过图床（2011 年开站）

免费图床能活 15 年是件很离谱的事。大部分同类活不过两年：服务器、带宽、人力都要钱，收不上来就关站，这是常态。

它游客上传 24 小时后自动删除，注册登录后长期存储，单图 10MB，支持 JPG/PNG/BMP，没有 API，页面带普通展示广告。

打开首页就能拖文件上传，不用注册。传完直接给直链、HTML、BBCode 三套嵌入代码，复制即用。10MB 上限够传高清截图和一般 gif。想长期存就注册个账号，图片不会被清掉。

它还没有被安全软件标记域名。有些图床服务本身没问题，但被滥用后触发了域名标记，导致在办公网、校园网里打不开。这个目前没这问题。

一句话：十五年老店，不折腾。这是我博客配图的备线，主力在 ImgBB，它负责兜底下不掉的那部分。

### 2. ImgBB（单图 32MB）

ImgBB 免费档无需注册、拖拽即传，单图 32MB 是这 8 个里最大的，上传时还能设自动删除时间（从「不删」到「6 个月后」自由选），有 API。传高分辨率原图、长截图、大尺寸 gif 都没压力。但匿名上传的图不好管理、删不掉，建议注册。

上传完自动生成直链、HTML 缩略图、BBCode、Markdown 四套链接。它的上传接口我的 skill 直接调用，填好 API Key 就能全局上传。

我的博客封面图全丢在它上面，传了几十张没出过问题，没 502、没失效。八年老站，体量在那儿，不至于突然跑路。

除非要传单张 100MB 的 RAW 原片，那不该用免费图床，去 NAS 自建。

### 3. 闪电图床

闪电图床是注册用户免费，最大 10MB，批量一次最多 7 张，速率限制每分钟 17 张、每天 127 张、每月 277 张，有接口文档、支持 API 对接（我的 skill 可接入）。

打开官网第一感觉就是干净，没有飘来飘去的广告横幅，没有「限时优惠」弹窗，就一个上传界面。注册后有仪表盘，能看到已上传列表，支持原图保存和无限流量。

277 张/月什么概念？一天发一篇配 3 张图，一个月也就 90 张，绰绰有余。速率限制只影响批量场景，一口气传 500 张产品图才要排队。普通写文章完全够。

公益站通病：哪天维护者不干了就可能不更新或关站。但好处是它没想从你身上赚钱，不会突然弹「额度用完请充值」。目前稳定运行，值当一个。

### 4. 聚合图床

聚合图床免费档给 500MB 存储、单次最多 10 张、每小时 100 次 API 请求，有 API。

它底层整合了七牛云、阿里云 OSS 等多家存储，上传时可切线路，你没把鸡蛋放一个篮子里，一条挂了还有其他家扛。配合 PWA，手机浏览器也能用。

免费方案单次 10 张、500MB、100 次/小时的限制，在 8 个里算比较紧的。只放博客封面和少量配图够用；大量图要管理得升级。

注意它是单页应用，必须开 JavaScript 才能加载，禁 JS 会白屏。

### 5. 零米图床

零米图床免费档单文件 5MB，每分钟 10 张、每小时 100 张、每天 100 张，并发 10 张，共 10GB 存储、仅可建 1 个相册，有完整 API 文档。

免费档限制要看仔细，每天只能传 100 张。听起来不少，但一篇博客配 5–10 张，一天发两篇就到顶。

更要命的是单文件 5MB。传一张原画画质截图就 4MB，几乎没余量。看漫画、传长图、4K 截图都用不上，这些得靠 32MB 大图图床。

10GB 空间看着大，但单文件 5MB + 每天 100 张，根本填不满，「免存储限制」对多数人是不存在的。

它确实没有付费套餐，干脆利落地把免费档额度设得很克制。定位很明确，不是给重度用户，是给「偶尔传一张图」的人准备的。

### 6. Postimages

Postimages 免费档单图 32MB，但直链图片最高分辨率仅 1280px（原图超过自动缩放），含广告，API 每月 1000 次。

32MB 看着香，但「直链锁死 1280px」是免费档最大坑。传 2560x1440 截图，展示自动缩成 1280px 宽。做技术教程截图，代码区小字缩完看不清。上传时可选「不调整大小」，那仅影响缩略图预览，免费直链仍强制缩放。

不需要高清展示，发论坛、插表情包、传头像，1280px 完全够。支持不注册匿名上传，临时分享方便。传完直接给直链、论坛代码、缩略图链接，上手简单。

### 7. PicGo.net

PicGo.net 注册后单图 25MB，支持源图直链、BBCode、HTML 缩略图，提供 API 集成。它和 PicGo 只是名字撞了，并不是同一个东西，第一次打开估计都愣一下。

注册后单图 25MB，上传完自动生成源图直链、BBCode、HTML 缩略图三种格式。功能说得过去，界面整齐。没特别亮点，也没糟缺陷。属于「能用」档。

想接进自动上传流程的，可以用它提供的 API 凭证接入。但匿名不支持，得先在网站上注册拿凭证。

### 8. img.remit.ee

img.remit.ee 是 2026 年冒出来的新面孔，单图 20MB，支持 JPG/PNG/GIF/WebP/HEIC/PDF，不限流量、不限上传数、不限总存储，无 API。

不限上传数在免费图床里罕见，大部分要么限单图大小、要么限总存储、要么限 API 次数。它直接「三个不限」，底气足。

支持 HEIC（iPhone 默认格式）和 PDF，苹果用户友好，不用先转 JPG。20MB 比 32MB 略少，但日常够。

唯一顾虑是太新。上线不到一年，没经历时间考验。免费图床第一年存活率最低，成本扛住就活，扛不住就公告迁移或消失。建议先当备胎存不重要的图，半年后还活着再考虑当主力。

## 避坑总结

实测完一圈，几个反复踩的点：

- 免费额度有时效：今天写的免费档，可能下季度就调。生产环境用前自己再确认一遍。
- 别绑死单一图床：我 ImgBB 主力 + 路过图床备线两条腿，哪天一条挂了另一条顶着，不至于全站裂图。
- 分辨率限制是隐坑：32MB 单图的大图图床，免费直链照样可能锁 1280px。要高清展示先确认直链分辨率。
- 公益 / 新图床当备胎：稳的当主力，太新或纯公益的存不重要的图，别把核心资产压上去。
- 「免费」不全信：没付费套餐不等于无限制，限流、限分辨率、限天数都是隐形天花板。
