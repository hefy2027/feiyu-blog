之前写过一篇「免费搭建文生图网站」的教程。当时从建 Worker、配 AI 绑定、调模型参数、写前端页面，一套下来虽然不算难，但步骤不少。后来发现 cf-manager 的 Store 里就有现成的 text2img 模板，搜一下、点部署，一个带完整 UI 的文生图网站就上线了。前后不超过三分钟。

之所以能这么省事，是因为 cf-manager 里藏了一个"应用商店"。66 个现成模板，搜一个、点一下，服务就上线了。这篇不聊面板本身（前面几篇讲过了），专门说说这个商店。

---

## 以前想搭个服务，门槛有多高

就拿短链来说。一个最简单的短链服务，逻辑无非是「短码 → 长链接」的映射。但如果从零做起：

- 新建一个 Cloudflare Worker，搞清楚 Workers 的基本写法和路由规则
- 新建一个 KV 命名空间，学会 KV 的读写 API
- 在 Worker 代码里把 KV 绑定进去，处理 GET 请求时查 KV 然后 301 跳转
- 绑个域名，配 HTTPS
- 想加个管理后台？再写一套前端页面

而对不写代码的人来说，这条路基本走不通。不是他们不想，是每一个环节都是一道坎。建 Worker 要写 JS，建 KV 要理解 key-value 模型，配绑定要搞清楚环境变量和 binding 的区别，域名还得去 DNS 后台手动加 CNAME。这一套下来，大部分人还没到"写短链逻辑"这一步就已经放弃了。

而短链只是冰山一角。图床需要 R2，你得搞清楚 bucket 怎么建、CORS 怎么配、上传接口怎么写；文生图需要配 Workers AI 的模型调用、处理 prompt 和参数的传递；临时邮箱需要 Worker 处理邮件逻辑，涉及 SMTP 协议和邮件解析。每个服务都是一套全新的学习曲线。到头来，这些东西你明明知道存在，但跟你没关系——因为你用不了。

---

## 66 个模板，挑一个就是你的

cf-manager 内置了一个应用商店（Store），从 `cf-store` 这个模板仓库拉取一份目录。目前里面有 **66 个现成模板**，覆盖的场景大概能分成这几类：

- **监控类**：站点状态页、SSL 证书到期监控，帮你盯着，挂了第一时间知道
- **工具类**：短链、文件分享、临时邮箱、IP 查询，日常高频需求
- **存储类**：图床、文件托管，挂在自己域名下的存储方案
- **内容类**：博客系统、笔记应用，连 CMS 都省了
- **AI 类**：Whisper 语音转文字等，把 AI 能力包装成即用服务

66 个模板不是 66 个项目让你去研究。更像超市货架，你不需要知道东西怎么造的，只需要知道哪个是你想要的。比如你想搭个文件分享服务，搜 "dingding" 就能找到丁丁快传；想给 Telegram 接个 AI 机器人，搜 "telegram" 就有现成的；想要个订阅链接转换工具，sublink-worker 也在里面。不需要看懂代码，甚至不需要知道它用的是什么技术栈。

![搜索和筛选](https://i.ibb.co/BKCch7k6/5f81172ef32d.png)

Store 页面长什么样？一个搜索框，一排分类标签，一列模板卡片。搜关键词，点开看介绍，看它需要什么资源（KV？D1？R2？），然后就到了最关键的步骤：

![Store 模板列表](https://i.ibb.co/9HtmTLds/39af4e2d0cbf.png)

## 实战：3 分钟搭一个文生图网站

回到开头那个 text2img 模板。我把它拆开讲一遍。

搜。在 Store 页输入 "text2img"，列表立刻过滤出这个模板。点开，看到一段介绍：基于 Cloudflare Workers AI 的文生图应用，支持 Flux、SDXL 等多模型，自带完整 Web UI。

![text2img 模板卡片](https://i.ibb.co/8DbKfpry/cfmanager-store-text2img-gif.gif)

看绑定。模板详情页会告诉你它需要什么资源。text2img 只需要一个 AI binding，用来调用 Cloudflare Workers AI 的模型。这个绑定面板会自动配好，你连看都不用看。

点部署。面板把 Worker 代码和 AI binding 一起推到你的 Cloudflare 账户上。因为不需要额外创建 KV、D1 或 R2，部署速度很快。

![一键部署弹窗](https://i.ibb.co/k6q0W5Zr/cfmanager-deploy-dialog-png.png)

验证。部署完打开分配的地址，一个完整的文生图页面就在眼前了。输入提示词，选模型，点生成——跟用 Midjourney 一样，但这是你自己的站点，跑在你自己账号的免费额度上。

![text2img 网站首页](https://i.ibb.co/nMCW1Rgm/text2img-web-ui-png.png)

整个过程我没写一行代码，没打开终端，没配环境变量。而之前写那篇教程的时候，光是配 AI 绑定、调 fetch 请求、写前端页面就折腾了好一阵。

多说一句面板在背后做的事：部署前它会跑一轮预检，检查 Worker 名称是否冲突、配置文件有没有差异。如果有冲突或警告，会弹出来让你确认。确认之后才真正执行部署。万一部署中途出问题，它还会自动回滚，把刚才创建的资源清理掉，不会留下一堆"孤儿"。这些逻辑如果自己写脚本处理，又是几百行代码。

![部署成功](https://i.ibb.co/BKsR4XzV/cfmanager-deploy-success-png.png)

## 顺手再来三个：短链、图床、临时邮箱

文生图搭完了，趁着手热，再展示几个不同类型的模板。你会发现操作路径一模一样。

短链 sink。搜 "sink"，点开。它依赖一个 KV 来存短码映射。面板自动帮你建好 KV 绑定，点部署。之后把长链接贴进去，生成短后缀就能用。

![sink 短链效果](https://i.ibb.co/XZLX3cZv/8e05342f4bce.png)

图床 PixR2。搜 "PixR2"，点开。它依赖 R2 存储桶。面板自动创建或复用 R2，点部署。之后拖图片上传就行，跟你平时用图床一样。

![PixR2 图床效果](https://i.ibb.co/6cg6qkwp/013877296bf2.png)

临时邮箱 smail。搜 "smail"，点开。这个更简单，几乎不需要额外资源，点部署就出来一个临时邮箱地址。注册一些不重要的网站时用，保护真实邮箱。

![smail 临时邮箱效果](https://i.ibb.co/5gD60ph9/cf-manager-store-04c-smail.png)

注意一个细节：text2img 依赖 AI、sink 依赖 KV、PixR2 依赖 R2、smail 几乎不需要额外资源——四种完全不同的绑定类型，但操作路径完全一样。搜，看绑定，点部署。学一次就够了。

另外提醒一下，Worker 部署完直接访问可能会报 1101 错误，这是 Cloudflare 的路由限制。去 Worker 设置里把自定义域名绑上就正常了，不是什么 bug，就是个必经步骤。

还有模板更新的问题。目前 Store 不会自动同步上游更新，需要手动重新部署。这个设计其实是故意的——自动更新可能导致线上服务突然行为变化，对于已经在用的服务来说反而是风险。想追新版本，重新部署一次就行，操作和第一次完全一样。

多说一句，cf-store 的模板源默认托管在 Surge 上，偶尔会抽风加载不出来。Store 页面里可以切到备用源（jsDelivr CDN 或 GitHub Raw），点两下就行。这个容错设计也是面板里埋的小心思。

![源地址设置](https://i.ibb.co/7JMPMCyz/61aa453a1aac.png)

## 你不需要会写代码，你只需要会挑

"搭服务"这件事，以前是开发者的专利。不是因为本质上有多难，而是流程里有太多非开发者迈不过去的坎：写代码、配环境、理解 KV/D1/R2 的 API、处理报错。这些坎把很多人挡在了外面。

模板市场把这些坎抹掉了。代码别人写好了，KV 和 D1 面板帮你创建，绑定自动配好。你唯一需要做的事情，是知道自己想要什么。

这有点像当年的 WordPress 主题市场。你不会写 PHP？挑个主题，点安装，你就有了一个网站。现在对 Cloudflare 生态来说，Store 在做类似的事——让 Worker 和 Pages 从"开发平台"变成"应用平台"。

Cloudflare 的免费额度摆在那里：Workers 每天 10 万次请求免费，KV 每天 10 万次读写免费，D1 每月 500 万行读取免费，R2 每月 10GB 存储免费，Workers AI 每天也有免费神经元额度。对个人和小团队来说，部署几个小服务基本不花钱。你搭的文生图、短链、图床，跑一个月可能连免费额度的零头都用不完。

如果你手里有几个 Cloudflare 账号，装好 cf-manager，打开 Store 页。剩下的就是逛。

另外，如果你自己也写过好用的 Worker 或 Pages 项目，可以考虑提交到 cf-store。66 个模板就是这么攒起来的——社区里的人把自己造过的轮子放上来，别人就不用再造一遍。你提交一个，货架上就多一个。

---

前几篇发完之后，陆续有人在后台问：Store 里的模板安全吗？第三方代码能用吗？我的回答是：cf-store 是官方源，代码都是开源的，部署前可以自己看一眼源码。当然，模板市场里也有社区提交的第三方项目，部署前扫一眼源码目录，确认逻辑确实是你要的，别闭眼点。这个习惯不只是 Store 需要，用任何开源项目都应该有。

至于能不能用，我装过的 text2img 跑了快一个月，没出过问题。图床和短链也一直在用。说白了，这些模板本质上就是别人已经踩过坑、调好参数的 Worker 和 Pages 项目，你直接复用，省掉的是试错成本。

模板市场做的事，说穿了就是把梯子放低一点，让更多人手能够到。
