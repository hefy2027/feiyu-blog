# 明确文章方向（grilling 多轮提问框架 · 应急兜底）

> ⚠️ **本文件仅为应急兜底**：正常情况下第一步应直接用 `use_skill` 工具加载 `grilling` 技能（或 `@command://grilling`）。**只有在该技能确实无法加载（环境报错 / 未安装）时**，才按本框架**多轮**向用户提问，直至方向清晰，再进入后续步骤。不要把它当作首选，也不要在 grilling 可用时自行替代。

不要一次性把所有问题抛给用户，应**按维度逐轮追问**，并根据上一轮回答逐步收敛。

## 五个维度

1. **主题定位与核心观点**
   - 这篇文章到底要解决用户什么？核心立场/结论是什么？
   - 是「盘点汇总」还是「带观点推荐」？是否要给出「最值得用」的结论？

2. **目标读者**
   - 开发者 / 技术新手 / 普通用户？
   - 决定术语深度、是否需要背景铺垫。

3. **覆盖范围（边界）**
   - 哪些子主题要写、哪些不写？
   - 例如「免费 AI IDE」「免费大模型 API」「统一端口 / OpenAI 兼容 endpoint」「各大厂新用户羊毛」——全写还是侧重？

4. **风格与深度**
   - 清单式薅羊毛汇总 / 深度评测对比 / 教程式实操？
   - 预期篇幅（短文 / 长文）？

5. **是否含实操**
   - 要不要给具体配置示例（base_url、endpoint、申请入口链接）？
   - 要不要可复制的命令 / 代码片段？

## 产出

明确后的：主题定位、核心观点、目标读者、覆盖范围、风格深度、是否含实操示例。作为后续调研 / 大纲 / 正文的输入。
